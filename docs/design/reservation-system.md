# 1on1 予約システム 設計メモ

- 作成日: 2026-10-02 / 改訂: 2026-10-16（DB 設計・フロント設計を反映）
- 開発方式: アジャイル（スプリントは区切らず、1 Issue = 1 PR で回す）
- 対象デバイス: スマホ / PC
- デプロイ先: Cloudflare Workers
- 前身: `seminar-1on1-GAS`（Googleスプレッドシート + GAS）
- DB の詳細: `docs/design/db-reservation.md` / `database.dbdiagram`

---

## 1. 目的

ゼミの1on1（発表・相談）予約を、スプレッドシートの日付タブ運用から
「カレンダーで日付を選ぶ → 空き枠を予約する」Webアプリに置き換える。

## 2. ユーザー

- ログイン: **Google ログイン必須**（better-auth）
- 利用可能アカウント: `@stu.musashino-u.ac.jp` / `@ds.musashino-u.ac.jp` / `@musashino-u.ac.jp`
  - Google の `hd` パラメータはヒントに過ぎないため、**サーバー側でメールドメインを必ず検証する**
  - `@` より後ろを3ドメインと **完全一致** で比較する（末尾一致にしない）

| 役割 | できること |
|---|---|
| student（学生） | 予約・取消 / 自分の予約一覧と発表回数を見る / 表示名を変える |
| teacher（先生） | 全体連絡を書く（自分の分を編集・削除）/ 全員の発表回数を見る。予約はしない |
| admin（管理者） | student の機能すべて / 全体連絡の管理（全員分）/ 他人の予約の取消 / 管理画面 |

- 新規ログインは `student`。最初の admin は手作業で DB を更新して作る
- 先生は初回のプロフィール登録で「教員（学年なし）」を選び、admin が役割を teacher に変える

### 公開範囲

| 情報 | 本人 | 他の学生 | 先生・管理者 |
|---|---|---|---|
| 予約者名・学年 | ○ | ○ | ○ |
| 発表回数 | ○ | × | ○（全員分） |

公開範囲の制御は **APIレスポンスで行う**（フロントで隠すだけにしない）。

### ログインの記録に保存するもの

`sessions` には、better-auth の標準どおり接続元の IP（`cf-connecting-ip`）と User-Agent を保存する（2026-10-22, Issue #2 で決定）。IP は回数制限で利用者を区別するためにも使う。

## 3. 課題

- 日付ごとにタブが増え続け、目的の日を探しにくい
- 人数が増え、同じセルへの同時書き込み・上書きが起こりうる
- スマホでのスプレッドシート編集は操作しづらい
- 「済」の判定がセル色（グレー）頼みで、手作業のミスが起きやすい

## 4. 機能

### MVP に含める

| # | 機能 | 誰が |
|---|---|---|
| 1 | Google ログイン（3ドメイン限定）＋ 初回プロフィール登録（表示名・学年） | 全員 |
| 2 | トップ：月カレンダー ＋ 今週の全体連絡 | 全員 |
| 3 | 日別の枠の表（スプシ風）→ 空き枠をクリック → 「予約しますか？」→ はい で確定 | student / admin |
| 4 | 自分の予約の確認・取消（マイページ / 日別の表の自分の名前から） | student / admin |
| 5 | マイページ：予約一覧・発表回数・表示名の変更（学年は変更不可） | 全員 |
| 6 | 全体連絡の作成・編集・削除（本人の分。admin は全員分） | teacher / admin |
| 7 | 発表回数一覧（全員分） | teacher / admin |
| 8 | 管理画面：休止日の登録（理由つき） | admin |
| 9 | 管理画面：日ごとの枠の編集 | admin |
| 10 | 管理画面：利用者一覧・役割の変更 | admin |
| 11 | 管理画面：学年更新（毎年4月。B4・MIDS B4・M2 は進路を選ぶ） | admin |
| 12 | 自動処理：今日（Asia/Tokyo）以降の金曜を4回分生成 / 毎晩、過ぎた予約を「済」にする | – |

### MVP に含めない（優先順）

1. アカウント画面の研究内容・研究ステップ（中身が未定）
2. 予約ルールの制限（1日1枠まで など）
3. 通知・リマインド（メール / Slack）
4. スプレッドシートからのデータ移行

### スプシから引き継がないもの

相談内容・要望・先生からの連絡（予約ごと）・日ごとのメモ。
先生からの連絡は全体連絡にまとめ、相談内容・要望は別ドキュメントで管理する。

## 5. 画面構成

```
[ログイン] ──(初回のみ)──> [プロフィール登録]  表示名・学年（「教員（学年なし）」も選べる）
     │                          │
     └────────────┬─────────────┘
                  ▼
[トップ]  /                   月カレンダー ＋ 今週の全体連絡（teacher / admin はここから書く）
  │ 日付をクリック（過去の日付も開ける）
  ▼
[日別の枠の表]  /days/:date    スプシ風の表（時限・開始・終了・予約者名）
  │ 空き枠をクリック                    自分の名前をクリック → 取消
  ▼
(ダイアログ)「13:30〜13:50 を予約しますか？」→ はい / いいえ

ヘッダーから:
├── [マイページ]  /me           表示名の変更・自分の予約一覧（取消）・発表回数
├── [発表回数一覧]  /stats      teacher / admin にだけボタンを表示
└── [管理画面]  /admin          admin にだけボタンを表示
      ├── 学年更新
      ├── 開催日の管理（休止・理由・枠の編集）
      └── 利用者の管理（役割の変更）
```

- 休止日はカレンダー上でグレー。PC ではカーソルを合わせると「休講日」と表示し、クリックで理由を表示する（スマホはタップで理由を表示）
- カレンダーの週の始まりは日曜 / 月曜から選べる（既定は日曜）。選んだものはその端末のブラウザに保存し、DB には持たない（2026-10-23, Issue #5 で決定）
- 日別の表には、発表枠・休憩・先生からの共有・なし をすべて行として並べる
- 確認ダイアログはブラウザ標準の `<dialog>` を使う
- 予約・取消のルール（2026-10-23, Issue #7 で決定）
  - 予約できるのは、開始時刻（日本時間）より前の枠だけ。当日でも開始時刻ちょうどからは予約できない
  - 本人が取り消せるのは、開始時刻より前で、まだ「済」になっていない予約だけ。admin は開始後の予約も「済」の予約も取り消せる
  - admin は日別の表で、全員の予約者名から取消できる（ダイアログには誰の予約かを出す）
  - 予約できない枠（発表以外・休止日・開始後）への予約は `409 SLOT_NOT_RESERVABLE`、埋まっている枠は `409 SLOT_TAKEN`、本人が取り消せない予約は `409 RESERVATION_NOT_CANCELABLE`
- マイページ（2026-10-29, Issue #8 で決定）
  - 予約一覧は「予約中」（日付の近い順）と「実施済み」（新しい順）に分ける
  - 開始時刻を過ぎた予約は、「済」になる前（当日、Cron の実行前）でも「実施済み」に入れる。発表回数は `done` の件数のため、反映は翌日になることを画面に添える（2026-10-29, Issue #8 のレビューで決定）
  - teacher は予約しないため、予約一覧と発表回数は出さず、表示名の変更だけを出す（API は teacher にも空の一覧と 0 を返す）
- ヘッダーには、アプリ名（トップへ）・マイページ・ログアウトを置く。ログインとプロフィール登録が要る画面（登録画面を除く）はすべて、親ルートでヘッダーとログイン確認を共有する（2026-10-29, Issue #8 で決定）。teacher / admin には、マイページの前に発表回数一覧も置く（2026-10-30, Issue #10 で決定）
- 全体連絡（2026-10-30, Issue #9 で決定）
  - 連絡は開催日ごとに書く（開催日は必須）。本文は 1〜1000 文字（絵文字1つ = 1文字）で、改行とタブは使える。タイトルは持たない
  - 表示期間：開始日が空なら作成日（日本時間）から、終了日が空なら開催日まで。編集しても作成日は変わらない（表示を始める日がずれないように）
  - 開始日と終了日の前後は、両方入っているときだけ API で確かめる（`400 VALIDATION_ERROR`。DB の CHECK 制約も同じ範囲）。空を補ったあとの期間で、これから表示される日が無い連絡は、画面で送らせない
  - 並び順は、表示を始める日の昇順。同じ日なら作成した順
  - 編集・削除できるのは、書いた本人と admin。書いた本人は、あとで役割が変わっても自分の分を直せる
  - 編集（PATCH）でも、すべての項目を送る（空の開始日・終了日は null）
  - 表示前の連絡はトップの一覧に出ないため、「表示前の連絡」として別に出す（teacher は自分の分、admin は全員分。`GET /api/announcements/upcoming`）。役割が変わった人は、自分の表示前の連絡が1件以上あるときだけ出す
  - トップの連絡欄はカレンダーの上に置き、書く・編集する入力欄は連絡欄の中で開く
  - 開催日の候補は、今日以降の開催日（休講日も「（休講）」を付けて選べる）を今月と来月の分から作る。Cron が4週分ずつ作るため2か月分で足りる。過去の開催日かどうかはサーバーでは確かめない
- 発表回数一覧（2026-10-30, Issue #10 で決定）
  - 載せるのは、予約できる役割（student / admin）で在籍中（`isEnrolled = true`）の、プロフィール登録済みの人。teacher と卒業生は載せない
  - 0 回の人も載せる（まだ発表していない人を見つけられるように）
  - 並び順は、学年（`GRADES` の順。学年の無い admin は最後）→ 表示名。表示名の順は DB の照合順序に従う（読みの50音順ではない）
  - 回数は `done` の件数。マイページと同じく、反映は翌日になることを画面に添える
  - student が URL を直接開いたときは、トップへ移さず「この画面は先生と管理者だけが見られます」と出す（なぜ見られないかが分かるように）
- 管理画面・休止日（2026-10-30, Issue #11 で決定）
  - 管理画面は `/admin` の下にタブで並べる（いまは「開催日の管理」`/admin/days` だけ。`/admin` を開くとそこへ移す）。admin かどうかは親ルートで1回だけ確かめ、admin 以外にはタブも中の画面も出さず「この画面は管理者だけが見られます」と出す
  - 休止・再開できるのは、今日（日本時間）以降の金曜だけ。今日より前は `409 SEMINAR_DAY_PAST`（過去の日を休止すると、実施済みの予約も消えて発表回数が減るため）。金曜以外は `400 VALIDATION_ERROR`
  - 休止理由は任意（理由なしは `null` を送る）。1行・100文字まで（絵文字1つ = 1文字）で、表示名と同じく見えない文字・制御文字は使えない
  - 休止すると、その日の開始前の枠の予約を消す（枠は残す）。今日を休止するとき、開始時刻を過ぎた枠の予約は発表済みのため残し、翌日の Cron で「済」にする（消すと発表回数が減るため。2026-10-30, Issue #11 のレビューで決定）
  - 再開すると理由を `null` に戻し、枠が1つも無い日だけ時間割どおりの枠を作る
  - 行が無い日（4週間より先など）は、休止なら `closed` の行を（枠は作らない）、再開なら `open` の行と時間割どおりの枠を作る
  - 休止と同時に予約されても休止日の開始前の枠に予約が残らないよう、予約の INSERT は開催日の行に共有ロック（`FOR SHARE`）を掛ける
  - 開催日の管理の画面は、月ごとにその月の金曜をすべて並べる（行の無い日は「未作成」）。休止は理由の入力 → 確認ダイアログ（予約が消えることを書く）の順で、結果に消した予約の件数を出す。理由の変更も休止と同じ値を送るため、画面が古く、ほかの管理者が開催日に戻していた場合に備えて、確認ダイアログに予約が消えることを書く

## 6. データ構造

詳細は `docs/design/db-reservation.md`（判断理由つき）と `database.dbdiagram` を参照。

```
users ──< reservations >── slots >── seminarDays
  │  └──< gradePromotions                  │
  └──────────< announcements >─────────────┘
```

| テーブル | 要点 |
|---|---|
| `users` | better-auth + `role` / `grade` / `displayName` / `isEnrolled` |
| `seminarDays` | `date` UNIQUE、`status`（open / closed）、`closedReason` |
| `slots` | `period`（3〜6）、開始・終了時刻、`kind`。UNIQUE(seminarDayId, startTime) |
| `reservations` | `slotId` UNIQUE で二重予約を防ぐ。取消は物理削除。`status`（reserved / done） |
| `announcements` | 開催日（`seminarDayId`）・書いた人（`authorId`）・本文（`body`）・表示期間（`displayFrom` / `displayUntil`、任意）。CHECK(`displayFrom <= displayUntil`) |
| `gradePromotions` | 学年更新の記録。`academicYear` UNIQUE で二重実行を防ぐ |

- 発表回数は列に持たず、`done` の予約の件数で出す
- 時間割テンプレートはコード定数（`src/shared/schedule-template.ts`。GAS の `SCHEDULE` を移植）

## 7. API 設計

| メソッド | パス | 権限 | 内容 |
|---|---|---|---|
| `*` | `/api/auth/*` | – | better-auth |
| GET | `/api/me` | ログイン済 | 自分の情報・役割・プロフィール登録済みか |
| POST | `/api/me/profile` | ログイン済 | 初回のプロフィール登録（表示名・学年）。登録済みなら `409` |
| PATCH | `/api/me/profile` | ログイン済 | 表示名の変更（学年を含むと `400`）。未登録なら `409` |
| GET | `/api/me/reservations` | ログイン済 | 自分の予約一覧 ＋ 発表回数 |
| GET | `/api/days?month=YYYY-MM` | ログイン済 | 月内の開催日・状態・休止理由・空き枠の数 |
| GET | `/api/days/:date` | ログイン済 | その日の枠と予約者名（休止日も枠を返す）。ログイン中の人が予約できるか・取り消せるかも返す。開催日でなければ `404` |
| POST | `/api/slots/:slotId/reservations` | student / admin | 予約。埋まっている・予約できない枠なら `409` |
| DELETE | `/api/reservations/:id` | 本人 / admin | 取消。本人でも開始後・「済」なら `409` |
| GET | `/api/announcements?current` | ログイン済 | 表示期間中の全体連絡 |
| GET | `/api/announcements/upcoming` | ログイン済 | 編集できる、表示前の全体連絡（teacher は自分の分、admin は全員分） |
| POST | `/api/announcements` | teacher / admin | 全体連絡の作成。開催日でない日付なら `404 SEMINAR_DAY_NOT_FOUND` |
| PATCH / DELETE | `/api/announcements/:id` | 書いた本人 / admin | 編集・削除。他人の連絡なら `403`、連絡が無ければ `404 ANNOUNCEMENT_NOT_FOUND`、（PATCH で）開催日でない日付なら `404 SEMINAR_DAY_NOT_FOUND` |
| GET | `/api/stats/presentations` | teacher / admin | 全員の発表回数 |
| POST | `/api/admin/grade-promotions` | admin | 学年更新（4月1日以降のみ実行可。同じ年度は `409`） |
| PATCH | `/api/admin/days/:date` | admin | 休止・再開と理由（行が無ければ作る。休止時は開始前の枠の予約を削除）。金曜以外は `400`、今日より前は `409 SEMINAR_DAY_PAST` |
| PATCH | `/api/admin/slots/:id` | admin | 枠の編集（`presentation` 以外にしたら予約を削除） |
| GET | `/api/admin/users` | admin | 利用者一覧 |
| PATCH | `/api/admin/users/:id` | admin | 役割の変更（最後の admin は変更不可、`409`） |
| (Cron) | `scheduled` | – | 今日（Asia/Tokyo）以降の金曜を4回分、冪等に生成 / 過ぎた予約を `done` にする |

- フロントからは Hono RPC クライアントで呼び出す
- 入力検証は zod（`src/shared/schemas.ts`）
- 成功は `200`（作成も含む）、競合は `409`、権限不足は `403`、エラーは `{ error: { code, message } }`（`docs/conventions/api.md`）
